## 1. FUNcube-1 (AO-73) の電波仕様とテレメトリ内部構造

### 1.1 一次情報・公式仕様
* **衛星名**: FUNcube-1 (AO-73 / AMSAT-OSCAR 73, NORAD ID: 39444)
* **開発元**: AMSAT-UK（英国アマチュア衛星通信協会）および RSGB（英国アマチュア無線連盟）
* **公式ポータル**: [AMSAT-UK FUNcube Project](https://funcube.org.uk/)
* **世界共通テレメトリ収集DB**: [FUNcube Data Warehouse](https://data.amsat-uk.org/)
* **復調リファレンス**: [gr-satellites (Daniel Estévez氏)](https://github.com/daniestevez/gr-satellites)

### 1.2 電波諸元と物理層・データリンク層
* **ダウンリンク中心周波数**: $145.935\ \text{MHz}$ (VHF 2m アマチュア宇宙無線バンド)
* **変調方式**: $1200\ \text{bps}$ BPSK (Binary Phase Shift Keying / 差動符号化 DBPSK)
* **前方誤り訂正 (AO-40 FEC 規格)**:
  * 畳み込み符号（Convolutional Code）: 符号化率 $r = 1/2$, 拘束長 $K = 7$（生成多項式 $G_1=171_8, G_2=133_8$）
  * リード・ソロモン符号: $\text{RS}(160, 128)$（短縮化リードソロモン符号）
  * 時間インターリーブ（ビット分散によるバースト誤り防止）
  * 32 ビット分散同期ワード（Distributed Syncword）によるフレーム同期

### 1.3 テレメトリの内部構造（ペイロードデータ）
FUNcube-1 のフレームは 256 バイトで構成され、宇宙空間の過酷な環境をリアルタイムに伝えるセンサデータが凝縮されています：

```text
【FUNcube-1 AO-40 テレメトリフレーム構造 (256 Bytes)】
┌─────────────────────────┬─────────────────────────┬─────────────────────────┐
│ リアルタイムテレメトリ   │ 全軌道データ (WOD)      │ フィッターメッセージ    │
│ (Real-time Telemetry)   │ (Whole Orbit Data)      │ (Fitter Message)        │
│ 60 Bytes                │ 160 Bytes               │ 36 Bytes                │
└─────────────────────────┴─────────────────────────┴─────────────────────────┘
```

1. **リアルタイム・ハウスキーピングテレメトリ (60 Bytes)**:
   * **太陽電池各面電圧・電流**: $+X, -X, +Y, -Y$ 面のセル起電力。太陽に対する衛星の三次元姿勢やスピン周期が算出可能。
   * **メインバッテリ電圧・充放電電流**: 通常 $8.2\text{V} \sim 8.4\text{V}$。
   * **各部温度センサ**: 太陽電池パネル（日照時 $+40^\circ\text{C}$ / 日陰時 $-20^\circ\text{C}$）、バッテリ温度、OBC（マイコン）温度、PA（高周波電力増幅器）温度。
   * **高周波増幅器 (PA) 状態**: 送信出力（Forward Power）およびアンテナ反射電力（Reflected Power / SWR）。
2. **全軌道データ (WOD: Whole Orbit Data - 160 Bytes) ★最大の特長**:
   * 衛星が地球を1周（約90〜100分）する間のセンサデータを **1分刻みで衛星内部メモリに蓄積した過去ログ**。
   * 日本上空を通過する一瞬（約10分間）を受信するだけで、**「地球の裏側（夜側・食＝エクリプス）を飛んでいたときのバッテリ放電や極低温の推移」** を完全に復元できる。
3. **フィッターメッセージ (36 Bytes)**:
   * 地上管制局（AMSAT-UK）からアップロードされた学校向けメッセージや挨拶テキスト。

### 1.4 地上局通知で「テレメトリ取得完了」と表示された背景
地上局デーモン（`apps/ground-station/src/decoder.rs`）は、SatDump に FUNcube-1 用のライブパイプラインが存在しない場合、フェイルファストとして「生IQ信号の保全完了」を示すフォールバック値を出力する設計になっていました。そのため、**宇宙からの生信号（`raw.u8`）はディスクに無傷で保存されているものの、パケットデコード処理は未実行** という状態でした。

## 2. 直交サンプリング（IQ検波）における DC オフセットと FLL トラップの物理

### 2.1 DC オフセット（0 Hz スパイク）の発生メカニズム
ダイレクトコンバージョン（ゼロIF）または低IF方式のSDR受信機（RTL-SDR Blog V4等）では、RF信号を中心周波数 $f_c$ の局発発振器（LO）と直交ミキサで乗算し、複素ベースバンド信号 $r(t) = I(t) + j Q(t)$ に変換します。

$$I(t) = s(t) \cos(2\pi f_c t) + V_{\text{dc}, I}$$
$$Q(t) = -s(t) \sin(2\pi f_c t) + V_{\text{dc}, Q}$$

ここで、$V_{\text{dc}, I}, V_{\text{dc}, Q}$ は半導体ミキサのLOリーク（局発信号の漏れ込み）やADC（A/D変換器）のオフセット電圧です。わずか数ミリボルトの直流偏位であっても、デジタル変換後のサンプリング列では **直流成分（周波数 0 Hz）の定数** となります。

### 2.2 なぜ FFT で 25〜30dB もの巨大な針状ピークになるのか？
サンプリング数 $N = 240,000$ 点の離散フーリエ変換（DFT）において、一定の微小直流バイアス $\epsilon$ が存在すると、0 Hz のビン（Bin 0）にエネルギーがコヒーレントに加算されます：

$$X[0] = \sum_{n=0}^{N-1} (x[n] + \epsilon) = \sum_{n=0}^{N-1} x[n] + N \epsilon$$

$N = 240,000$ の場合、$N$ 倍の増幅効果により、パワースペクトル密度（PSD）ではノイズフロアに対して **$+25\text{dB} \sim +30\text{dB}$ の極めて鋭利な針状ピーク（DC Spike）** として現れます。

### 2.3 FLL（周波数位相同期ループ）の「DC トラップ」
BPSK 信号の復調では、受信信号の搬送波周波数偏差（ドップラー偏移）を自動追従するために **FLL (Frequency Locked Loop)** や **Costas Loop** が用いられます。

1. **トラップの発生**:
   FLL は通過帯域内で最も電力密度の高いキャリアを引き込もうとします。0 Hz に 28dB 超の強力な無変調 DC スパイクが居座っていると、FLL は本物の BPSK 信号ではなく、**この無変調の 0 Hz スパイクにロックオン** してしまいます。
2. **デコードの空振り**:
   DC スパイクは情報を持たない直流であるため、復調器の出力シンボルは反転のない平坦なデータ（ゼロまたは固定値）となり、AO-40 デフレーマ（相関同期器）は同期ワードを検出できず、完全に空振り（フレーム数 0）となります。

### 2.4 対策アルゴリズム
1. **直流平均除去（DC Removal）**:
   データ列から平均値を減算することで、0 Hz のインパルスを数学的にゼロ化する。
   $$c[n] \leftarrow c[n] - \frac{1}{N} \sum_{k=0}^{N-1} c[k]$$
2. **適正レートへのデシメーション（48 kHz化）**:
   $1200\ \text{bps}$ の狭帯域信号に対し、$240\ \text{kSPS}$ は 1 シンボルあたり 200 サンプルと過大であり、整合フィルタ（RRC: Root Raised Cosine）のタップ数が膨大になって引き込み範囲が狭まります。$48\ \text{kHz}$（1 シンボル 40 サンプル）へダウンサンプリングすることで、フィルタが安定してロックするようになります。

## 3. ガウス白色雑音における極値統計学（Gumbel 極値分布）による SNR 判定の数学

受信信号を解析した際、ピーク周波数がランダムに変動しつつも、実測 SNR が常に **$12.3\text{dB} \sim 13.5\text{dB}$（約 12.5dB）** で一定になる現象が観測されました。この現象は、**極値統計学（Extreme Value Theory）** によって厳密に説明されます。

### 3.1 基礎方程式（雑音ピークと中央値の差の期待値）

$$E[\max(\text{Noise}) - \text{median}(\text{Noise})] \approx 10 \log_{10}(\ln N) - 10 \log_{10}(\ln 2) \approx \mathbf{12.52\ \text{dB}} \quad (N = 240,000)$$

### 3.2 記号一覧

| 記号 | 物理的・数学的意味 | 単位 / 代表値 |
| :--- | :--- | :--- |
| $N$ | FFT（離散フーリエ変換）の総ビン数（サンプル数） | $240,000$ |
| $X_k$ | 各周波数ビン $k$ における複素ガウス雑音振幅 | 複素数 ($\mathcal{CN}(0, \sigma^2)$) |
| $P_k = \|X_k\|^2$ | 各周波数ビンの電力（パワースペクトル密度） | 指数分布 ($\text{Exp}(\lambda)$) |
| $\sigma^2$ | ガウス雑音の分散（ノイズ電力） | $\text{W}$ または無次元 |
| $\text{median}(\text{Noise})$ | パワースペクトル中央値（ノイズフロアの推定量） | $\sigma^2 \ln 2$ |
| $\max(\text{Noise})$ | $N$ 個の独立な雑音ビンの中で最大の電力（見かけのピーク） | ガンベル極値分布に従う確率変数 |

### 3.3 日本語での読み解き
「衛星の電波が一切届いておらず、アンテナから入ってくるものが純粋な熱雑音（ホワイトノイズ）だけであっても、$240,000$ 個の周波数ビンを並べれば、**確率統計的に最も高い雑音の突起は、中央値（ノイズフロア）よりも約 12.5 dB 高い場所に必ず出現する**」ことを主張しています。

したがって、**実測 SNR が 12.5 dB 前後で周波数が定まらない場合、それは電波を受信しているのではなく、熱雑音の統計的ゆらぎの最高峰を観測しているに過ぎない** という判定基準が数学的に導かれます。

### 3.4 展開ステップ・直感イメージ

1. **各ビンの電力分布**:
   時間領域の複素ガウス白色雑音を FFT 変換すると、各ビンの実部と虚部は互いに独立な正規分布 $\mathcal{N}(0, \sigma^2/2)$ に従います。
   電力 $P_k = I_k^2 + Q_k^2$ は自由度 2 のカイ二乗分布、すなわちパラメータ $\lambda = 1/\sigma^2$ の **指数分布** に従います：
   $$F(x) = P(P_k \le x) = 1 - e^{-x/\sigma^2}$$

2. **中央値の導出**:
   累積確率が $0.5$ となる値 $x_{\text{med}}$ は：
   $$1 - e^{-x_{\text{med}}/\sigma^2} = 0.5 \implies x_{\text{med}} = \sigma^2 \ln 2$$
   デシベル表記では：
   $$10 \log_{10}(x_{\text{med}}) = 10 \log_{10}(\sigma^2) + 10 \log_{10}(\ln 2) \approx 10 \log_{10}(\sigma^2) - 1.59\ \text{dB}$$

3. **$N$ 個の最大値（極値統計学）**:
   $N$ 個の独立同分布（i.i.d.）な指数分布の最大値 $M_N = \max(P_1, \dots, P_N)$ の分布は、フィッシャー・ティペット・グネデンコ定理により **ガンベル極値分布（Type I 極値分布）** に収束します。
   その最頻値（特性極値）$u_N$ は、$1 - F(u_N) = \frac{1}{N}$ より：
   $$e^{-u_N/\sigma^2} = \frac{1}{N} \implies u_N = \sigma^2 \ln N$$
   最大値の期待値はオイラー・マスケローニ定数 $\gamma \approx 0.5772$ を用いて $E[M_N] \approx \sigma^2 (\ln N + \gamma)$ となりますが、主要項は $\sigma^2 \ln N$ です。
   $N = 240,000$ を代入すると：
   $$\ln(240,000) \approx 12.388$$
   デシベル表記では：
   $$10 \log_{10}(u_N) = 10 \log_{10}(\sigma^2) + 10 \log_{10}(12.388) \approx 10 \log_{10}(\sigma^2) + 10.93\ \text{dB}$$

4. **ピーク対中央値の比（見かけのSNR）**:
   $$\Delta \text{SNR} = 10 \log_{10}\left( \frac{u_N}{x_{\text{med}}} \right) = 10.93\ \text{dB} - (-1.59\ \text{dB}) = \mathbf{12.52\ \text{dB}}$$

## 4. マンション東向きベランダ（5階）における受信ジオメトリと建物遮蔽の電磁気学

### 4.1 ベランダの幾何学的配置（ジオメトリ）

```text
【マンション5階・東向きベランダの受信ジオメトリ】

                     西 (背後・建物躯体側)                     東 (前面・関東平野/太平洋側)
           ══════════════════════════════════════════╦
           [ 住戸・部屋 / 鉄筋コンクリート外壁・梁 ]  ║
           (145MHz電波遮蔽: -30dB 〜 -50dB！)        ║    ベランダ (5階・海抜約200m)
                                                     ║  ┌─────────────────────────┐
                                                     ║  │                         │  📡 アンテナ
                                                     ╚══╧═════════════════════════╧═══ (東へチルト)
                                                                           ＼
                                                                             ＼  見通し視界 (Line of Sight)
                                                                               ＼   遮蔽物ゼロの関東平野・太平洋
                                                                                 ＼  (見通し距離 100km超)
                                                                                   🛰️ 東側通過衛星 (直達波直撃！)
```

### 4.2 鉄筋コンクリート（RC造）によるファラデーケージ遮蔽
1. **波長と鉄筋グリッドの物理対比**:
   * $145\ \text{MHz}$ 帯（VHF）の電磁波の波長は $\lambda = \frac{c}{f} = \frac{3 \times 10^8}{145 \times 10^6} \approx 2.07\ \text{m}$ です。
   * マンション外壁・スラブ内部に配筋されている鉄筋メッシュの間隔（グリッドピッチ $d$）は一般に **$10\text{cm} \sim 20\text{cm}$** です。
   * $d \ll \lambda$（波長がグリッド間隔の10倍以上大きい）であるため、鉄筋メッシュは電磁波に対して導体平面板、すなわち **ファラデーケージ（電磁シールド）** として振る舞います。
2. **遮蔽減衰量**:
   * コンクリート自体の誘電損失に加え、鉄筋による完全反射により、背後（西側）から飛来する電波の透過損失は **$30\text{dB} \sim 50\text{dB}$（電力比で $1/1,000 \sim 1/100,000$）** に達します。

### 4.3 CubeSat の微弱リンクバジェット（死角通過の限界）
* **送信電力の比較**:
  * 大型極軌道気象衛星（Meteor-M / NOAA）: 送信電力 **$5\text{W} \sim 10\text{W}$**（$+37\text{dBm} \sim +40\text{dBm}$）
  * 1U CubeSat（FUNcube-1 等）: 送信電力 **$30\text{mW} \sim 300\text{mW}$**（$+15\text{dBm} \sim +25\text{dBm}$）
* **自由空間伝搬損失 (FSPL)**:
  高度 $600\text{km}$、仰角 $60^\circ$ 時の距離約 $700\text{km}$ における伝搬損失は：
  $$\text{FSPL} = 20 \log_{10}(d) + 20 \log_{10}(f) + 32.44 \approx 132.6\ \text{dB}$$
* **受信電力の計算**:
  * 直達波（東側通過）: $+25\text{dBm} (\text{300mW}) - 132.6\text{dB} + 2\text{dBi} \approx \mathbf{-105.6\ \text{dBm}}$（SDR のノイズフロア $-120\text{dBm}$ に対し **SNR 約 $+15\text{dB}$ で明瞭に復調可能**）
  * 遮蔽波（西側通過）: $-105.6\text{dBm} - 40\text{dB} (\text{RC壁減衰}) = \mathbf{-145.6\ \text{dBm}}$（**ノイズフロアを $25\text{dB}$ 下回り、電波は完全に消失**）

### 4.4 昼パス（日照時）と夜パス（エクリプス時）の運用プロファイル
FUNcube-1 は電力管理システム（EPS）により、日照状態に応じて送信モードを自動遷移させます：
* **昼パス（日照下）**: 太陽電池が $2.5\text{W} \sim 3.0\text{W}$ 発電し、バッテリが満充電（$8.4\text{V}$）。教育用ビーコンを **$300\text{mW}$（大電力モード）** で連続送信。
* **夜パス（食・エクリプス）**: 発電ゼロ。過放電防止のためトランスポンダーを休止し、ビーコン出力を **$30\text{mW}$（10分の1の省電力モード）** に減力。

## 5. アマチュア衛星 FM 中継器（SO-50）の運用メカニズム

### 5.1 衛星概要と通信方式
* **衛星名**: SO-50 (Saudi-OSCAR 50, NORAD ID: 27607)
* **アップリンク**: $144.980\ \text{MHz}$（FM / CTCSS トーン必須）
* **ダウンリンク**: $436.795\ \text{MHz}$（FM 音声, 送信出力 $250\text{mW}$）
* **一次情報**: [AMSAT SO-50 Information](https://www.amsat.org/so-50/)

### 5.2 オンデマンド・スケルチタイマーの動作原理
SO-50 は常時電波を出しているわけではありません：
1. **中継器の起動（Arming）**:
   地上局が $144.980\ \text{MHz}$ に **$67.0\ \text{Hz}$** のサブオーディオトーン（CTCSS / PLトーン）を付加して電波を送信すると、衛星内部のデコーダがトーンを検出し、**10分間タイマー** を起動してトランスポンダー送信機が ON になります。
2. **休眠時の挙動**:
   10分間誰も交信を行わないと、衛星は自動的に送信機をシャットダウンします。
3. **深夜パスで録音された音声の真相**:
   今朝 03:09 のパスで録音された `raw.wav` が全区間 `RMS: 2900` フラットであったのは、**深夜帯で誰も中継器を起動しておらず、衛星の送信機が OFF だったため、SDRのFMディスクリミネータが宇宙と大気の熱雑音（FMヒスノイズ）のみを出力していた** ことが理由です。
   交信が活発な夕方や休日のパスを受信すれば、中継器が開いて賑やかな交信音声がクリアに復調されます。

## 6. 実践デコードパイプライン（Python 高速前処理 ＋ gr-satellites）

生IQデータ（`raw.u8`）から DC オフセットを除去し、`gr-satellites` 最適な $48\ \text{kHz}$ IQ WAV を生成してデコードする標準スクリプトです。

### 6.1 高速前処理スクリプト (`preprocess_iq.py`)

```python
import wave
import numpy as np
from scipy import signal

def convert_raw_u8_to_48k_wav(raw_path: str, out_wav_path: str, fs_in: int = 240000, fs_out: int = 48000):
    decimation = fs_in // fs_out # 240k -> 48k (factor: 5)
    
    # 1. 8bit unsigned IQ を読み込み
    with open(raw_path, "rb") as f:
        raw_bytes = np.fromfile(f, dtype=np.uint8)
    
    # 2. -1.0 ~ +1.0 の複素数 float32 に正規化
    iq_float = (raw_bytes.astype(np.float32) - 127.5) / 128.0
    c = iq_float[0::2] + 1j * iq_float[1::2]
    
    # 3. 【最重要】DC オフセットの完全消去
    c = c - np.mean(c)
    
    # 4. アンチエイリアス LPF 適用 & 5分の1デシメーション
    c_48k = signal.decimate(c, decimation)
    
    # 5. 16bit PCM ステレオ WAV (Left=I, Right=Q) として書き出し
    i_16 = np.clip(np.real(c_48k) * 32767, -32768, 32767).astype(np.int16)
    q_16 = np.clip(np.imag(c_48k) * 32767, -32768, 32767).astype(np.int16)
    iq_stereo = np.empty((len(i_16) * 2,), dtype=np.int16)
    iq_stereo[0::2] = i_16
    iq_stereo[1::2] = q_16
    
    with wave.open(out_wav_path, "wb") as wf:
        wf.setnchannels(2)
        wf.setsampwidth(2)
        wf.setframerate(fs_out)
        wf.writeframes(iq_stereo.tobytes())
    
    print(f"✅ 変換完了: {out_wav_path} (48kHz Stereo IQ WAV)")

if __name__ == "__main__":
    convert_raw_u8_to_48k_wav("raw.u8", "funcube_48k.wav")
```
