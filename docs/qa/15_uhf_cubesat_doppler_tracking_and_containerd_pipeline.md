# 🛰️ UHF帯（435MHz）CubeSat観測・ドップラーS字解析とCRI containerdパイプライン詳解

本ドキュメントは、固定長15cmアンテナと北向きベランダ（マンション5階）という物理環境において、なぜUHF帯（435〜438MHz）のCubeSat電波観測が最適解となるのか、その電磁気学・軌道力学的メカニズムを解説するとともに、エッジコンピューティング（KubeEdge / containerd）におけるコンテナ配信設計を体系的に解説します。

---

## 1. アンテナ長 15cm とグランドプレーン共振の物理

### 1.1 モノポールアンテナの電気的鏡像効果（Image Theory）

アンテナはベランダのエアコン室外機上の金属板（グランドプレーン）に設置されています。
導体表面の境界条件（電場の接線成分がゼロ）により、導体板の下側に逆位相の電荷分布が生じ、あたかも地下に対称なエレメントが存在するかのように振る舞います。これにより、物理長 $L$ のモノポールアンテナは、全長 $2L$ のダイポールアンテナと同等の放射パターンを形成します。

```
       │  +q (エレメント長 L)
       │
═══════╧═══════  接地導体板 (グランドプレーン)
       ┆
       ┆  -q (電気的鏡像 -L)
```

### 1.2 1/4波長共振の基本数理

エレメント内部の進行波と先端での反射波が同相で重なり合って定在波が立つ条件は、エレメント長 $L$ が波長 $\lambda$ の $1/4$（往復で半波長 $\lambda/2$）になるときです。

$$f = \frac{c \cdot k}{4 L}$$

| 記号 | 物理的意味 | 設計値 | 単位 |
| :--- | :--- | :--- | :--- |
| $f$ | 基本共振周波数（Resonance Frequency） | 約 $475 \times 10^6$ | $\text{Hz}$ |
| $c$ | 真空中の光速度 | $299,792,458$ | $\text{m/s}$ |
| $L$ | アンテナエレメントの物理長 | $0.15$ | $\text{m}$ |
| $k$ | アンテナ先端の端面効果による波長短縮率（Velocity Factor） | 約 $0.95$ | 無次元 |

#### 日本語での読み解き
物理長 $15\,\text{cm}$ のホイップアンテナは、**$430 \sim 480\,\text{MHz}$（UHF 帯）** に極めて良好に共振します。
この周波数においてアンテナの入力インピーダンスは純抵抗（約 $36\,\Omega$）となり、RTL-SDR の標準インピーダンス（$50\,\Omega$）とほぼ無反射（VSWR $\approx 1.38$）で結合するため、微弱な宇宙電波をロスなく受信機へ導くことができます。

## 2. 北向きベランダと太陽同期極軌道（Polar Orbit）の幾何学

### 2.1 太陽電波との対比と除外理由
北半球において太陽は南天（東 $\to$ 南 $\to$ 西）を通過します。南側がマンションの鉄筋コンクリート（RC）躯体で遮蔽されている北向きベランダでは、太陽光・太陽電波を直視することは物理的に不可能です。

### 2.2 極軌道衛星の飛来ジオメトリ
世界中の大学や研究機関が運用する CubeSat、および地球観測衛星（NOAA, Meteor等）の大多数は、軌道傾斜角約 $98^\circ$ の**太陽同期極軌道（Sun-Synchronous Polar Orbit）** を飛行しています。

```
                [ 北極 ]
                   │
                   │  ↓ 衛星の進行方向（北→南パス）
              北向きベランダ
      ═════════════╤═════════════
                   │ [ RC躯体による南側遮蔽 ]
                [ 南極 ]
```

- **視界条件**: 西〜北〜東（方位角 $270^\circ \le \theta_{\text{az}} \le 90^\circ$）が開けており、手すりを抜ける仰角 $\theta_{\text{el}} \ge 10^\circ$ の空域を確保。
- **軌道力学的優位性**: 極軌道衛星が北極上空を通過して日本付近にアプローチしてくるパス（北 $\to$ 南）、または日本を抜けて北極方向へ離脱していくパス（南 $\to$ 北）を、一切の障害物なく真正面から長時間捉えることができます。

## 3. ドップラー効果と「S字カーブ」の数学的メカニズム

低軌道衛星（LEO: 高度約 $400 \sim 600\,\text{km}$）は、第1宇宙速度に近い秒速約 $7.5\,\text{km/s}$ で頭上を駆け抜けます。この高速移動により、電波の受信周波数にドップラー偏移が発生します。

### 3.1 ドップラー偏移の基本方程式

$$f_{\text{rx}}(t) = f_0 \left( 1 - \frac{v_r(t)}{c} \right)$$
$$\Delta f(t) = f_{\text{rx}}(t) - f_0 = - f_0 \frac{v_r(t)}{c}$$

| 記号 | 物理的意味 | 代表値 | 単位 |
| :--- | :--- | :--- | :--- |
| $f_0$ | 衛星の送信中心周波数 | $437.500 \times 10^6$ | $\text{Hz}$ |
| $f_{\text{rx}}(t)$ | 観測点で受信される瞬間周波数 | 時間変化 | $\text{Hz}$ |
| $\Delta f(t)$ | ドップラー周波数偏移 | 最大約 $\pm 10.875$ | $\text{kHz}$ |
| $v_r(t)$ | 観測者から見た衛星の視線速度（Radial Velocity） | $-7.5 \times 10^3 \sim +7.5 \times 10^3$ | $\text{m/s}$ |
| $c$ | 光速 | $3.0 \times 10^8$ | $\text{m/s}$ |

### 3.2 S字カーブの展開ステップと直感イメージ

観測者から衛星への相対位置ベクトルを $\vec{r}(t)$、相対速度ベクトルを $\vec{v}(t)$ とすると、視線速度は以下の内積で定義されます。

$$v_r(t) = \frac{\vec{r}(t) \cdot \vec{v}(t)}{\|\vec{r}(t)\|}$$

1. **接近フェーズ（AOS $\to$ TCA 手前）**:
   - 衛星が観測者に向かって接近するため、位置ベクトルと速度ベクトルが対向（$\vec{r} \cdot \vec{v} < 0$）。
   - 視線速度は負（$v_r < 0$）となり、$\Delta f(t) > 0$（周波数が公称周波数より約 $+10\,\text{kHz}$ 高く受信される）。
2. **最接近点（TCA: Time of Closest Approach）**:
   - 衛星が最も観測者に近づいた瞬間、速度ベクトルは位置ベクトルと直交（$\vec{r} \cdot \vec{v} = 0$）。
   - 視線速度が瞬間的にゼロ（$v_r = 0$）となり、$\Delta f = 0$（実測周波数が公称値 $f_0$ と完全に一致するゼロクロス）。
   - ドップラー変化率 $\frac{d(\Delta f)}{dt}$ はこの TCA で最大傾きを記録します。
3. **離脱フェーズ（TCA $\to$ LOS）**:
   - 衛星が観測者から遠ざかるため、内積は正（$\vec{r} \cdot \vec{v} > 0$）。
   - 視線速度は正（$v_r > 0$）となり、$\Delta f(t) < 0$（周波数が約 $-10\,\text{kHz}$ 低く受信される）。

この「$+10\,\text{kHz} \to 0\,\text{Hz} \to -10\,\text{kHz}$」への連続的な推移が、Grafana の時系列グラフ上に滑らかな**ドップラーS字カーブ**として可視化されます。

## 4. エッジコンテナ基盤における CRI containerd とローカルレジストリ選定理由

### 4.1 なぜ Docker daemon（dockerd）を排除するのか？
Kubernetes v1.24 以降、中間の翻訳レイヤーであった `dockershim` は完全に廃止されました。
k3s および KubeEdge は標準で CRI（Container Runtime Interface）gRPC 仕様に準拠した **`containerd`** を内包しています。

```
【冗長な構成（排除）】
Kubelet (Edged) ──> dockershim ──> dockerd ──> containerd ──> runc ──> Container
   ※ GPD Pocket3 のメモリ（数百MB）とCPUを浪費

【本システムの統一構成（CRI直接連携）】
Kubelet (Edged) ──(gRPC)──> containerd (/run/k3s/containerd/containerd.sock) ──> runc ──> Container
   ※ 最軽量・ゼロオーバーヘッド
```

### 4.2 クラスタ内レジストリ（`registry:2`）による高速イテレーション
外部の Docker Hub や GitHub Packages (`ghcr.io`) を使わず、k3s 上の Pod として `localhost:5000` の OCI レジストリを立ち上げることで、以下のメリットを獲得します。

1. **オフライン・ゼロ遅延開発**:
   - `nerdctl` で containerd ソケットへ直接ビルドし、`localhost:5000` へプッシュ。外部インターネット回線を一切介さず数秒でデプロイが完了します。
2. **将来の2台分離へのシームレスな移行**:
   - 将来分析PC（Ubuntu）を追加した際も、Cloud側の IP（例: `192.168.1.100:5000`）を k3s の `registries.yaml` にミラー登録しておくだけで、Edgeノード（GPD Pocket3）が LAN 経由でイメージを直引きできます。
