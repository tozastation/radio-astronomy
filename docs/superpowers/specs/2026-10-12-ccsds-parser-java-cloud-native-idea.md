# やりたいこと: CCSDS パーサーを Java で書き、クラウドネイティブに運用する

- **作成日**: 2026-10-12
- **ステータス**: 構想メモ（未着手）。着手するときに設計仕様書と実装計画へ分ける

いまの `satellite-analyzer` は、Meteor-M の LRPT（デジタル画像放送）の復号を [SatDump](https://github.com/SatDump/SatDump) に任せています。このメモは、その中の CCSDS の層を自分で書き、JVM から GraalVM Native Image へ移し、OpenTelemetry で運用を見えるようにする、という次の題材をまとめたものです。

狙いは「SRE とクラウドネイティブに慣れた人が、宇宙の決まりを守ったまま地上局を実装すると、こうなる」を形にすることです。宇宙の側の形式（CCSDS、XTCE、要件と試験の対応）はそのまま使い、運用と監視をクラウドネイティブにします。

## 1. なぜ Java か

宇宙のソフトウェアは、どこで動くかで言語が分かれます。

| 領域 | 主な言語 |
| :--- | :--- |
| 衛星やロケットに積むソフト（搭載ソフト） | C、C++、Ada、最近は Rust |
| 地上の運用管制（テレメトリ、コマンド、追跡管制） | Java が多い。ほかに C++ |
| 軌道の計算 | Java（[Orekit](https://www.orekit.org/)）、C++、Fortran |
| 衛星データの処理 | Python が中心 |

NEC グループの地上系の求人は Java/JavaScript や Java/C++ を求めるので、地上の運用管制に寄せて Java で書きます。中心の部分を、あとで「起動後にメモリを確保しない」C 版として書き直す案も残しておきます。

## 2. パーサーを層ごとに作る

参照する規格は、CCSDS（宇宙データシステム諮問委員会）の [Blue Books](https://public.ccsds.org/Publications/BlueBooks.aspx) です。主に次の3つを読みます。

- TM Synchronization and Channel Coding（同期と誤り訂正）
- AOS Space Data Link Protocol（フレームの形）
- Space Packet Protocol（パケットの形）

入力は、リポジトリにある `apps/satellite-analyzer/assets/meteor_m2_sample.cadu` です。CADU は、区切りの印と、CCSDS の決まりで組んだフレームを一つにしたかたまりです。

最初に、SatDump が出す `.cadu` が、どこまで処理済みかを確かめます。誤り訂正（Reed-Solomon）と、データにかけた乱数パターンの除去（デランダマイズ）が済んでいるかどうかで、2番目の層の作り方が変わります。

| 順 | 層 | やること |
| :--- | :--- | :--- |
| 1 | 同期 | 区切りの印 `0x1ACFFC1D` を探し、フレームの切れ目を合わせる。ビット単位のずれと、ビットの反転も扱う |
| 2 | 誤り訂正の確認 | Reed-Solomon で直せたか、直せなかったかを数える |
| 3 | フレームの見出し | 版、衛星の番号、仮想チャネル（一本の電波の中を用途ごとに分けた通り道）、24 ビットの通し番号を読む。通し番号の飛びで、フレームの抜けを見つける |
| 4 | パケットのつなぎ直し | 宇宙パケットはフレームの境目をまたぐ。見出しの「最初のパケットの先頭位置」を手がかりにつなぎ直す。フレームが抜けたら、壊れたパケットを捨てて次のパケットから立て直す |
| 5 | 宛先ごとの振り分け | パケットの宛先の番号（APID）ごとに、画像の各チャネルなどへ分ける |

最初の一歩は、1番目と3番目だけです。CADU を読み、区切りの印を見つけて、衛星の番号と通し番号を出すところまでを作ります。

いちばん深掘りするのは4番目です。何が壊れて、どう立て直したかを説明できるようにします。

APID ごとの中身の定義（どのビットが何の値か）は、テレメトリとコマンドの定義の標準 [XTCE](https://www.omg.org/spec/XTCE/) で書きます。

## 3. 検証: 要件と試験を一本の線でたどる

- 要件に番号を振り、「〜しなければならない」の一文で書く。例は「通し番号の飛びを検出しなければならない」。
- 要件ごとに、試験、解析、検査、実演のどれで確かめるかを決める。
- 要件と試験の対応表を作り、両方向にたどれるようにする。
- 同じ録音で、SatDump の出力を正解として、自分のパーサーの結果と突き合わせる試験を作る。
- CI で、試験の結果と対応表を自動で出す。

## 4. JVM から GraalVM Native Image へ

いまの解析は、KEDA で 0 台から起動します。JVM は起動して温まるまでに時間がかかるので、0 台から起動する構成との相性はよくありません。

そこで、まず JVM で動かして測り、次に [GraalVM Native Image](https://www.graalvm.org/latest/reference-manual/native-image/) へ変えて、同じものを測ります。

前後で比べる数字は次の4つです。

- 起動から、最初のフレームを処理するまでの時間
- メモリの使用量と、その最大値
- コンテナのイメージの大きさ
- 一回の通過の録音を解析し終えるまでの時間。長く動かすと JVM が速くなる場合があるので、両方を正直に出す

JVM の側では、軽くする手も試します。

- jlink で、必要なモジュールだけのランタイムを作る
- JDK 25 の AOT キャッシュ（[JEP 483](https://openjdk.org/jeps/483)、[JEP 514](https://openjdk.org/jeps/514)、[JEP 515](https://openjdk.org/jeps/515)）
- オブジェクトの見出しを小さくする機能（[JEP 519](https://openjdk.org/jeps/519)）
- `-XX:MaxRAMPercentage` と SerialGC

組み込み方は、SatDump と同じです。`satellite-analyzer` の処理から、Native Image のバイナリを一回ずつ呼びます。Java のプロセスはクラスタに常駐させません。

Native Image では、JMX と JFR はビルドのときに有効にしないと使えません。ガベージコレクタの選択肢も、JVM より少なくなります。JVM で見えていた数字のうち何が見えなくなり、何で代わりに見たかも、比べる話の一部として残します。

## 5. 監視: OpenTelemetry と Micrometer

### 運用の数字（主役）

- 同期を見失った回数
- 通し番号の飛び（抜けたフレームの数）
- 誤り訂正で直せなかったフレームの数
- パケットのつなぎ直しに失敗した数
- APID ごとのパケット数

### 実行環境の数字（脇役）

- ヒープの使用量
- ガベージコレクションの停止時間
- スレッドの数

数字は [Micrometer](https://micrometer.io/) で集めます。トレースは [OpenTelemetry Java](https://opentelemetry.io/docs/languages/java/) で取ります。

トレースは、衛星の一回の通過ごとに一本作ります。その中に、同期、誤り訂正、フレームの見出し、つなぎ直しの区間（スパン）を置きます。区間には、衛星の番号、仮想チャネル、APID、抜けたフレームの数を属性として付けます。

一回の通過を解析して終わるプロセスは、Prometheus が数字を取りに来る前に終わってしまいます。数字は、次のどれかで残します。

- OTLP（OpenTelemetry の形式）で、こちらから送る
- Pushgateway へ送る
- 結果の JSON に書いて Garage の `results/` に置く

## 6. 宇宙の運用の言葉との対応

README か設計の文書に、この対応表を置きます。

| クラウドネイティブの言葉 | 宇宙の運用の言葉 |
| :--- | :--- |
| SLI / SLO | データ欠損率、パスごとの受信成功率 |
| 分散トレース | パスごとの処理記録と、欠損の原因の追跡 |
| IaC / GitOps | 構成管理と変更管理 |
| 0 台からの自動起動 | 衛星が来たときだけ資源を使う、パスに合わせた運用 |
| CI でのテスト | 要件ごとの検証の記録を自動で作る |

## 7. 読んで答え合わせするもの

- [Yamcs](https://yamcs.org/): Java で書かれた、オープンソースの運用管制システム。CCSDS のフレームとパケットを扱い、XTCE にも対応している
- [Orekit](https://www.orekit.org/): Java の軌道計算ライブラリ。TLE、SGP4、時刻の体系（UTC、TAI）、座標系。軌道と時刻は自作せず、これに任せる
- [SEI CERT Oracle Coding Standard for Java](https://wiki.sei.cmu.edu/confluence/display/java/): 基本のコーディング規約
- JPL Institutional Coding Standard for Java、ESA BSSC Java Coding Standards: 宇宙機関が Java に何を求めたかを知るための規約

## 8. あとで足したいこと

- 複数の衛星の通過が重なったときに、1 台の受信機をどの衛星に使うかを決める仕組み。優先度と、成功率の実績を使う。衛星コンステレーションの運用で、地上局を割り当てる問題の小さい版にあたる
- 中心の部分の C 版。起動後にメモリを確保せず、固定長のバッファだけを使い、壊れた入力でも落ちないようにする
